### 3. 质量评估工具与方法

课程环境无法使用 Gitee、SonarQube 等在线代码质量平台，本次采用本地等效工具链评估，评估方法与命令由组长统一发布，各成员使用同一版本工具，确保数据可复现：

```powershell
# 圈复杂度、可维护性指数、原始指标
python -m radon cc <app> -s -a
python -m radon mi <app> -s
python -m radon raw <app> -s

# 静态检查（需先设置 Django 配置环境变量）
python -m pylint <app> --load-plugins=pylint_django --django-settings-module=djangoblog.settings --ignore=migrations --score=y

# 代码风格检查
python -m pycodestyle <app> --max-line-length=120 --statistics --exclude=migrations

# 单元测试与覆盖率
python manage.py test <app> --noinput
```

评估要求：迁移目录 `migrations` 不纳入人工整改范围；报告中所有数据须来自实际命令输出，不得估算或编造；问题按"严重/一般/提示"三级归类，整改后使用同一命令复测并记录前后对比。

## 六、下一步系统优化计划要点

在完成第7-8周质量评估与整改的基础上，小组下一阶段的系统优化方向如下（详细分析、数据与实施步骤见代码质量分析报告）：

1. **性能优化（重点）**：排查视图与模型中的 N+1 查询，合理使用 `select_related`、`prefetch_related` 与批量查询；对评论反应统计、文章列表等高频路径做查询次数核对，减少重复查询与循环内查询。
2. **测试覆盖率提升**：以核心业务（文章发布与编辑、评论提交与审核、用户登录与资料）为重点补充视图层与业务逻辑测试，形成可重复执行的测试基线，后续改动以此回归。
3. **代码规范落地**：将《Python 编码规范》中的命名、排版、注释、Django 专项要求落实到提交前自查与工具检查环节，逐步把存量告警清零。
4. **依赖与仓库治理**：清理虚拟环境、日志、缓存等无关文件，补充 `.gitignore` 规则；核对 `requirements.txt` 依赖版本，保证成员环境一致、可复现安装。
5. **持续集成检查**：在现有 GitHub Actions 基础上补充或完善后端 `manage.py check`、单元测试与静态检查步骤，使合并前自动发现格式与测试问题。
6. **安全与配置规范**：数据库口令、邮件与第三方登录密钥等一律通过环境变量注入，生产环境关闭调试模式，提交材料中不出现敏感信息。
7. **文档持续维护**：接口与模型变更后同步更新设计说明书与注释，保持文档、注释与代码三者一致，避免文档滞后。

上述优化项按优先级安排到后续两周任务中，先解决性能与仓库治理问题，再逐步推进测试覆盖与持续集成建设。
